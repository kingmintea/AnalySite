# AnalySite

한국 주소를 입력하면 필지의 면적, 개별공시지가, 용도지역/지구 지정 여부, 도시계획도(용도지역·지적도)를 조회하는 웹사이트입니다.

구현 배경과 상세 설계는 [PLAN.md](./PLAN.md)를 참고하세요.

## 실행 방법

```bash
npm install
npm run dev                # http://localhost:3000
```

API 키·설정값은 프로젝트 루트의 `.env` 파일 하나로 관리한다(예전에는 `.env.example` 템플릿을 따로
뒀지만, 이 저장소는 git 저장소가 아니라 커밋 유출 위험이 없어 혼동을 줄이려고 `.env` 하나로 합쳤다).
새 키를 추가할 때는 이 `.env` 파일에 바로 채워 넣으면 된다.

`.env`의 `VWORLD_API_KEY`를 채우지 않으면 서버가 자동으로 **MOCK 모드**로 동작하여 "서울특별시 성북구 안암동2가 40" 예시 데이터로 프론트/지도 UI를 확인할 수 있습니다.

## API 키 발급

- V-World: https://www.vworld.kr → Open API 인증키 발급 (도메인 등록 필요)
- **공공데이터포털(data.go.kr)은 별도로 필요 없습니다.** 2024년 국가공간정보포털(NSDI) 서비스 통합으로
  토지이용계획정보/개별공시지가정보가 V-World API로 제공되며, data.go.kr에서 해당 API를 신청하면
  V-World로 안내(리디렉션)됩니다.

### 도메인 등록 관련 주의사항

V-World는 인증키 발급 시 등록한 도메인과 요청의 `domain` 파라미터 값이 정확히 일치해야
통과합니다(실제 요청의 Referer가 아니라 우리가 보내는 문자열 값을 비교하는 방식으로 실키
테스트에서 확인함). `.env`의 `VWORLD_DOMAIN`/`VWORLD_GATEWAY_DOMAIN`을 V-World 마이페이지에
등록한 도메인과 동일하게 맞추면 됩니다(로컬 개발 중에도 등록한 도메인 문자열을 그대로 사용).
불일치 시 연속지적도/용도지역 조회가 `INCORRECT_KEY` 또는 referer 불일치 오류로 실패합니다.

- 네이버 지도: https://console.ncloud.com → Services > AI·NAVER API > Application > Maps 로 클라이언트 ID 발급
  (Dynamic Map 상품 체크 필요). **Web 서비스 URL을 여러 개 등록할 수 있으며**, 로컬 개발 시에는
  운영 도메인(예: `https://kim-mintae.com`)과 별도로 `http://localhost:3000`(포트 포함, 경로 제외)을
  추가 등록해야 로컬에서도 지도가 뜬다(실키 테스트로 확인 — 미등록 시 `500 Internal Server Error`로 실패,
  V-World처럼 명확한 "URL 불일치" 메시지가 아니라 원인 파악이 어려울 수 있음에 주의).

- 기상청 실시간 날씨: https://www.data.go.kr → "기상청_단기예보 조회서비스" 활용신청(자동승인) →
  서비스키를 `DATA_GO_KR_WEATHER_KEY`에 입력. 비어 있으면 기후정보 탭의 "현재 기온/습도/강수량" 카드만
  목데이터로 동작하고, 아래 계절 평년값 비교는 키 없이도 항상 실데이터로 동작한다.

- 도로명주소 검색: https://business.juso.go.kr → 주소기반산업지원서비스 API 키를 `JUSO_API_KEY`에 입력.
  검색창에 입력하면 서버 프록시(`/api/address-search`)를 통해 도로명주소 후보와 지번주소를 자동 제시한다.

- 네이버 주변 시설 검색: https://console.ncloud.com → **NAVER API HUB**(네이버 지도용 "Maps" 상품과는
  별개 상품)에서 지역검색 키 발급 → `NAVER_SEARCH_CLIENT_ID`/`NAVER_SEARCH_CLIENT_SECRET`에 입력.
  옛 "네이버 개발자센터"(openapi.naver.com) 지역검색은 신규 신청이 이미 종료돼 더 이상 발급받을 수
  없으므로 반드시 API HUB 경로로 신청해야 한다. 현재 한시적으로 무료(검색 카테고리 API 합산 월
  775,000건, 추후 유료 전환 시 사전 공지 예정). 비어 있으면 "네이버 지도" 탭의 "주변 시설" 카드가
  목데이터로 동작한다. 엔드포인트(`https://naverapihub.apigw.ntruss.com/search/v1/local`), 인증 헤더
  (`X-NCP-APIGW-API-KEY-ID`/`X-NCP-APIGW-API-KEY`), 응답 좌표(`mapx`/`mapy` = WGS84 경위도 × 10^7)는
  모두 실키로 검증 완료. 지역검색은 좌표 반경 검색이 아니라 키워드 검색이라, 서버가 검색어 앞에 동
  이름을 붙여서(`{동이름} {카테고리}`) 인근 결과가 상위로 오도록 보정한다.

### 네이버 지도 — 지도 유형 전환·거리뷰

같은 네이버 지도 클라이언트 ID만으로 되는 기능이라 새 키가 필요 없다. 지도 유형(일반/위성/하이브리드/
지형)은 `naver.maps.MapTypeId`로, 거리뷰는 `naver.maps.Panorama` 서브모듈(스크립트에 `submodules=panorama`
추가)로 구현했다. 둘 다 실키로 정상 동작 확인했고, NCP Maps 공식 요금표에도 별도 과금 항목이 없어
기존 Dynamic Map 이용량에 포함되는 것으로 보인다(대표 계정 기준 월 600만 건까지 무료).

### 연간 절기별 기후 평년값 (기온/강수량/습도/풍속)

기상청 API가 아니라 **정적 데이터**를 사용한다: 기상자료개방포털(data.kma.go.kr)의 "우리나라
기후평년값(1991-2020) 계절별평년값"을 1회 수집해 `server/data/climateNormals.json`에 저장해두고,
매 요청마다 이 파일에서 가장 가까운 관측소를 찾아(하버사인 거리) 응답한다. 평년값은 세계기상기구
권고로 10년 주기로만 갱신되는 값이라 매번 외부 호출할 이유가 없고, 이 데이터를 제공하는 페이지는
공식 문서화된 Open API가 아니라 웹사이트 내부용 엔드포인트라 실행 시점 의존성을 줄이는 편이 안전하다는
판단에서다. "부지에 가장 가까운 관측소 1곳"을 그대로 시/지역 대표값으로 사용하며(사용자 확인),
"전국 평균"은 수집된 관측소 218곳 전체의 평균이다. 평년값을 다시 수집하려면 위 페이지에서
`selectAverage30YearsKoreaAjax.do`(POST, `schGubun=4`)를 호출해 갱신할 것.

### 건폐율·용적률 / 관련 법령

역시 정적 데이터다. 「국토의 계획 및 이용에 관한 법률 시행령」 제84조(건폐율)·제85조(용적률)의
용도지역별 법정 상한/범위를 `server/data/zoningLimits.json`에 표로 저장해두고, `/api/parcel-info`가
반환하는 `landUse[].name`(예: "제2종일반주거지역")과 매칭해 건폐율 상한·용적률 범위를 붙여준다.
법정 조례로 정해지는 **실제 적용 수치가 아니라 법령상 상한/범위**라는 점을 화면에 항상 고지한다
(지역지구가 아닌 지구단위계획구역 등은 전국 공통 수치가 없어 매칭되지 않을 수 있음).

### 층별 매싱(면적) 계산기

토지정보 탭의 "건폐율·용적률" 카드 안에 있는 "면적 계산기" 버튼으로 여는 순수 클라이언트 사이드 도구
(`public/js/massingCalculator.js`). 이미 조회된 대지면적·법정 건폐율/용적률만 있으면 되므로 서버 API를
호출하지 않는다. "구상 단계"(실제 치수, 기본 mm)와 "모형 단계"(모형 치수 + 축척 1:10~1:200 적용, 기본 cm)
두 모드를 지원하며, 층별로 가로×세로 또는 면적을 직접 입력하면 건축면적(층 중 최대)과 연면적(전 층 합)을
법정 허용 범위와 비교해 시각화한다. 건폐율(건축면적)은 시행령상 상한이 하나뿐이라 충족/초과 2단계로
판정하지만, 용적률(연면적)은 시행령이 "OO% 이상 XX% 이하"의 범위만 정하고 실제로는 그 범위 안에서
지자체 도시·군계획조례가 기준 수치를 따로 정하며 조례상 완화·인센티브 조건을 충족하면 시행령의 절대
상한까지 늘어날 수 있는 구조라(사용자 확인), 3단계로 판정한다 — 조례 기준 이내(문제없음) / 기준 초과~
절대상한 이내(조례 조건 충족 시 가능, 지자체 확인 필요) / 절대상한 초과. 다만 개별 지자체 조례가 실제로
정한 기준 수치는 지자체마다 달라 이 계산기가 정적으로 갖고 있지 않으므로, "조례 기준 참고치"는 시행령상
하한을 대신 쓴 값이라는 점과 정확한 수치는 토지이음 등에서 확인해야 한다는 점을 화면에 항상 고지한다.
대지면적 대비 건축면적/연면적 비율(%)도 각각 큰 글씨로 함께 보여준다.
면적 직접입력은 현재 선택된 치수 단위의
제곱(mm²/cm²/m²)으로 해석하고, 가로×세로와 동일하게 모형 단계에서는 축척의 제곱을 적용해 실제 면적으로
환산한다. 입력 중 매 글자마다 표 전체를 다시 그리면 포커스가 끊겨 소수점을 입력하기 어려워지므로,
타이핑 시에는 계산값만 갱신하고(구조가 바뀌는 조작에서만 전체 재렌더) input에 1 증감 스피너도 숨겨뒀다.
층을 추가할 때마다 대지(점선 바닥면) 위로 박스가 쌓이는 등각(isometric) 시각화도 함께 보여준다
(`public/js/isometricViz.js`, 순수 SVG). 실제 가로×세로 비율은 무시하고 모든 층(과 대지)을
면적의 제곱근을 한 변으로 하는 정사각형으로 단순화해 "쌓이는 느낌"에 집중했다.

### 동 평균 공시지가 대비 막대

"개별공시지가" 카드에 이 필지의 공시지가가 같은 법정동 평균 대비 몇 %인지 막대로 보여준다
(`server/services/dongLandPrice.js`). PNU 앞 10자리(법정동코드)로 V-World 연속지적도 API를
`attrFilter=pnu:like:<법정동코드>%`로 조회하면 같은 동의 모든 필지가 나오는 것을 실키로 확인했다
— 필지가 매우 많은 동은 최대 300필지까지만 표본으로 평균을 낸다(전수조사 아님). 동일 동은 30분 캐시.

### 기후 요약 및 설계 고려사항 (규칙 기반)

"연간 절기별 평균" 막대그래프 위에 한 줄 요약과 건물 설계 시 고려할 점을 보여준다
(`public/js/climateInsights.js`, 순수 클라이언트 계산). 실제 LLM을 호출하지 않고, 이미 응답받은
계절별 기후평년값(이 지점 vs 전국 평균)에서 가장 유의미하게 차이 나는 지표 1~2개를 문장으로
조합하고, 절대값 기준 임계값(예: 겨울 평균기온 0℃ 이하, 여름 습도 75% 이상 등)에 걸리는 항목을
최대 3개까지 골라 설계 고려사항으로 보여준다.

## 서버 API

| 엔드포인트 | 설명 |
| --- | --- |
| `GET /api/geocode?address=` | 주소 → 좌표(및 지번주소인 경우 PNU) |
| `GET /api/pnu?x=&y=` | 좌표 → PNU/면적/지목 (연속지적도 조회) |
| `GET /api/land-use?x=&y=` | 용도지역 목록 (신규 게이트웨이, 도메인 등록 필요) |
| `GET /api/land-price?x=&y=` | 개별공시지가 (연속지적도 응답에 포함되어 내려옴) |
| `GET /api/parcel-info?address=` | 위 항목을 모두 조합한 통합 조회 (프론트에서 사용) |
| `GET /api/map/wms?...` | V-World WMS 타일 프록시 (키 미노출) |
| `GET /api/config` | 프론트에 필요한 공개 설정값(네이버 지도 클라이언트 ID) 전달 |
| `GET /api/weather?x=&y=` | 기상청 초단기실황(현재 기온/습도/강수량) + 전국 15개 도시 비교 |
| `GET /api/climate-normals?x=&y=` | 계절별(봄/여름/가을/겨울) 기후평년값(기온/강수량/습도/풍속/일조시간) — 가장 가까운 관측소 vs 전국 평균 |
| `GET /api/nearby-places?x=&y=&categories=` | 부지 인근 주변 시설(지하철역/버스정류장/편의점/공원/학교 등) 검색 |
